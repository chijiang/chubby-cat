# Desk Kitty：开发计划与功能清单

日期：2026-10-23 · 状态：规划草案，尚未开始产品实现

用户已明确：macOS 优先；宠物猫浮在其他应用上方；连接 OpenAI-compatible API 进行 quick QA；连续使用屏幕 90 分钟后，猫走向屏幕中央、放大提醒，再慢慢回到原位。

本文其余参数均为建议默认值，可在开发前调整。这里的“最上方”理解为窗口层级置顶，猫本身可拖到屏幕任意位置。

## 1. 产品定位与首版边界

一只平时安静陪伴、随时回答小问题、在长时间使用电脑后主动关心用户的桌面猫。

首版的成功标准：无需打开主窗口即可提问；猫不干扰正常点击和打字；提醒动作完整、可取消；离线和 API 报错不影响计时与提醒。

- 平台建议：macOS 14+，优先验证 Apple Silicon；Intel 支持进入发布前兼容性评估，不默认承诺。
- 形态建议：菜单栏常驻程序 + 透明宠物浮层 + 独立问答面板 + 设置窗口。
- 美术方向已由用户指定：以提供的银灰虎斑猫照片设计卡通形象，保留黄绿色眼睛、白胸口、白手套与环纹尾巴；先完成基础动作，皮肤扩展留到后续。角色与动画帧方案见 [小猫形象与动画帧设计](cat-animation-design.md)。
- 首版不做：语音、自动读屏、自动读取剪贴板、文件操作、工具调用、账号同步、养成经济、应用商店和多宠物。
- 首版无需自建云后端；请求从本机发到用户指定的 API 服务，费用由对应服务计算。

## 2. 关键体验：90 分钟后的那只猫

### 2.1 建议动作脚本

1. 平时：猫待在用户拖放的位置，做低频眨眼、呼吸或打盹动作。
2. 达到 90 分钟：记录当前屏幕与位置，进入单次提醒流程。
3. 走向中央：朝猫当前所在显示器的可用区域中心移动，按距离与步速计算时间，目标约 2–5 秒；面向移动方向，避免滑着走。
4. 放大提醒：约 0.5 秒放大到原来的 1.8 倍，伸懒腰并显示固定文案：“已经看屏幕 90 分钟啦，陪我休息一下眼睛吧。”
5. 停留：约 6–8 秒，提供“开始休息”“10 分钟后提醒”“本轮跳过”。
6. 回家：无论用户选择还是停留超时，猫都缩回正常大小，以低于去程的速度走回记录的位置；时长按距离计算。

这些是产品交互参数，不代表健康效果承诺。提醒不依赖模型生成，不因网络延迟卡住。

### 2.2 不打扰规则

- 行走、放大和气泡出现均不主动取得键盘焦点；用户点击问答后才进入输入状态。
- 仅猫和气泡按钮接收点击；周围透明区域须能操作下面的应用。需要验证实际命中行为，不能仅依赖视觉透明。
- 提醒面板取得焦点时支持 Esc 关闭；没有焦点时不全局截获用户的 Esc。菜单栏始终提供取消提醒入口。
- 用户拖动猫时中断自动行走，以拖放后的坐标作为新位置；关闭气泡、显示器断开也能安全结束动画。
- 用户启用“减少动态效果”时，改成原地轻微放大或淡入提示，不跨屏幕行走。
- 不覆盖锁屏、系统授权弹窗等系统界面；普通应用上方置顶与系统级覆盖分别看待。

## 3. 计时与休息规则

### 3.1 “连续使用”的首版定义

采用“屏幕使用时段”的近似：应用运行期间，用户会话可用且显示器未休眠时累计。阅读和观看视频时即使没有键鼠操作，也继续计时；不以键鼠空闲直接断定用户离开。

本产品不能判断用户是否真的看着屏幕。首版不调用摄像头、不采集按键内容、不申请屏幕录制权限。离开电脑但屏幕仍亮着的情况可能高估使用时长，这是明确的测量边界。

- 锁屏、显示器休眠、系统休眠、切换到其他用户会话：暂停累计。
- 上述不可用状态连续达到 5 分钟：视为一次休息，下一次恢复使用时从 0 开始；不足 5 分钟则接续之前的累计时间。
- 手动“暂停计时”：冻结累计，不自动认定为完成休息；恢复时接续。
- “开始休息”：猫回位、计时暂停，启动建议 5 分钟的休息倒计时；倒计时后由用户确认完成再重置。计时结束本身不证明用户离开了屏幕。
- “10 分钟后提醒”：不清零使用时长，只把下一次提示推迟 10 分钟；暂停期间不消耗这 10 分钟。
- “本轮跳过”：明确结束这一轮，从当前时刻重新开始 90 分钟周期；不计入已完成休息。
- 气泡超时或普通关闭：采用 10 分钟稍后提醒，避免每秒反复触发。
- 本机重启或程序重开：恢复最近持久化的累计值，但不计入应用未运行的间隔，也不凭该间隔推定已经休息。
- 不同显示器的时间不叠加；整台电脑只有一个提醒周期。

5 分钟休息阈值及 90 分钟周期是建议默认值；后续可开放调整。使用单调时钟计算运行间隔，持久化累计值和状态，避免系统时钟调整造成跳变。

### 3.2 冲突处理

- 正在拖动、设置或输入问答时，记录“提醒待处理”，互动结束后再开始动画；菜单栏显示已到提醒时间。
- API 正在生成但用户未输入时可提示，不取消生成；用户打开问答时，猫先安全回位再打开面板。
- 用户可从菜单栏启用免打扰 30 分钟、1 小时或直到关闭；其间继续计时、暂停中央动画，结束后最多补发一次待处理提醒。
- 首版采用手动免打扰，不默认承诺自动识别会议、屏幕共享或所有全屏应用；全屏窗口显示行为进入技术验证。

## 4. 功能清单

### P0：首版必须交付

桌面宠物：

- [ ] 无边框透明浮层，普通应用上方置顶，非交互状态不抢焦点。
- [ ] 拖动位置、位置记忆、隐藏与重新显示、菜单栏退出。
- [ ] 呼吸眨眼、行走、伸懒腰、思考、说话、打盹六组基础动画，每组六个设计关键帧；左右行走复用镜像资源。逐帧对齐与运行时导出在接入前完成。
- [ ] 最小可行的多显示器适配：在猫所在屏幕提醒；拔掉外接屏后迁移到主屏可见区域。
- [ ] 透明区交互穿透，菜单栏一键暂停动画与提醒。

快捷问答：

- [ ] 点击猫或可配置全局快捷键打开输入框；快捷键冲突可提示并修改。
- [ ] 文本发送、流式输出、停止生成、复制回答、新建会话。
- [ ] 保留有限轮当前会话上下文，设置长度上限；默认简洁回答，可继续追问。
- [ ] 会话默认只驻留内存；关闭面板保留，退出程序清除；不自动附带其他应用或剪贴板内容。
- [ ] 配置 Base URL、API Key、Model，显示当前服务地址，提供测试连接。
- [ ] 首版兼容范围明确限定为 Chat Completions 风格的文字请求与 SSE 流；支持同一契约的非流式模式，不承诺所有标称 compatible 的扩展。
- [ ] 正确处理 URL 路径拼接，避免重复 `/v1` 或接口后缀；不强制依赖模型列表接口成功。
- [ ] 处理无效密钥、模型不存在、限流、断网、超时与服务端错误；保留输入，允许用户重试。
- [ ] SSE 按事件边界解析，能处理分片 JSON、结束标记和中途取消；非流式使用显式配置或清楚提示后切换，避免无声重复请求。
- [ ] 允许无密钥的本地兼容服务；远程默认 HTTPS，本地回环 HTTP 单独处理。

休息提醒：

- [ ] 90 分钟累计、暂停/恢复、休息判定、稍后提醒、本轮跳过。
- [ ] 完整“记录位置 → 走向中央 → 放大提示 → 缩小 → 缓慢回位”。
- [ ] 任一时刻最多一个提醒流程；重复系统事件不重复弹出。
- [ ] 免打扰、减少动态效果、剩余时间查看、手动立即演示提醒。
- [ ] 本地保存计时检查点；网络与模型状态不会阻塞提醒。

设置与交付：

- [ ] API 设置、猫的大小、提醒开关、快捷键、开机启动开关。
- [ ] 密钥存入 macOS Keychain；日志不写入密钥、完整聊天或敏感请求头。
- [ ] 清除会话、删除凭证、恢复设置；首版默认无遥测。
- [ ] Apple Silicon 安装包、签名和公证流程；首次配置与无 API 模式可用。

### P1：首版验证后补充

- [ ] 自定义提醒周期、休息时长、稍后提醒间隔。
- [ ] 多套原创猫皮肤、性格和聊天语气；轻量抚摸互动。
- [ ] 多个服务配置、快速切换模型、本地模型服务使用引导。
- [ ] 用户主动开启的本地聊天历史与导出。
- [ ] 自动更新、性能优化、Intel Mac 发行验证。
- [ ] 根据用户反馈评估全屏/会议应用免打扰，先验证权限与可靠性。

### P2：形成使用习惯后再考虑

- [ ] Windows 版本；重新评估客户端复用方案。
- [ ] 语音问答、选中文字提问、显式触发的截图问答。
- [ ] 本地使用时长与休息记录展示；明确区分完成休息和跳过。
- [ ] 更丰富的互动和可选长期记忆。

## 5. 技术方案建议

推荐 Swift + AppKit + SwiftUI，而非现在就为多平台增加桥接层。这是针对 macOS 优先、长期常驻、系统窗口行为重要的工程判断，实际资源占用需实测。

- AppKit：负责宠物透明窗口、浮动层级、屏幕坐标、拖动、菜单栏和系统事件；以 NSPanel / NSWindow 做非激活浮层的可行性验证。相关公开能力见 [NSPanel](https://developer.apple.com/documentation/appkit/nspanel)、[nonactivatingPanel](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/nonactivatingpanel) 和 [CollectionBehavior](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct)。
- SwiftUI：设置、问答面板、提醒气泡等界面。宠物帧动画先采用轻量序列帧与 Core Animation，复杂互动出现后再评估 SpriteKit。
- URLSession + Swift Concurrency：封装兼容服务请求、取消及流式响应。官方提供异步字节流能力：[URLSession](https://developer.apple.com/documentation/Foundation/URLSession)。
- Keychain + 本地配置文件：分别保存凭证与非敏感设置。凭证方案参考 [Keychain services](https://developer.apple.com/documentation/security/keychain-services)。
- 系统状态适配器：显示器与系统休眠、用户会话切换事件；显示器休眠可参考 [screensDidSleepNotification](https://developer.apple.com/documentation/appkit/nsworkspace/screensdidsleepnotification)。锁屏与会话切换不是同一事件，锁屏观测的公开 API、可靠性和恢复路径须单独验证。
- 分发：首版建议直接发布经过 Developer ID 签名、公证的安装包；App Store 作为独立发行任务评估。参考 [Apple 公证流程](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)。

备选方案：若团队以 TypeScript 为主、且 Windows 很快进入范围，可选 Electron + React。其窗口与电源状态接口能覆盖部分基础能力，但需要实测常驻成本，仍要处理 macOS 特有窗口行为。官方参考：[BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window)、[powerMonitor](https://github.com/electron/website/blob/main/docs/latest/api/power-monitor.md)。Tauri 可作为另一备选，但不作为当前默认方案。

### 模块职责

1. PetWindowController：浮层、显示器和位置恢复，不处理 API 与计时政策。
2. PetAnimator：朝向、帧序列、移动、缩放及中断后的收尾。
3. ScreenSessionTracker：把系统状态转换为可计时或暂停事件。
4. BreakScheduler：纯逻辑计算累计时间、待提醒、稍后提醒和重置；允许注入时钟进行测试。
5. ReminderCoordinator：协调提醒、拖动、聊天、免打扰，保证只有一个动画流程。
6. ChatService：兼容 API 适配、流式解析、取消和错误映射。
7. SettingsStore / CredentialStore：配置、计时检查点、密钥存取。

聊天、计时、动画分别管理状态，统一由协调器处理冲突，避免一个 API 超时让整只猫失去响应。

## 6. 开发阶段与交付物

估算前提：1 位熟悉 Swift/macOS 的开发者，使用现成授权素材或已有美术支持；约 20–30 个工作日，按 4–6 周安排。全新角色设计、复杂骨骼动画和发行账号准备另计。以下工期是估算，不是承诺。

### 阶段 0：验证系统窗口与计时信号，2–3 天

- 用占位图验证透明浮层、不抢焦点、交互穿透、移动缩放、Spaces、全屏和多显示器。
- 验证锁屏、显示器休眠、系统休眠与会话切换的观测路径，检查是否需要额外权限。
- 实测空闲 CPU、内存和动画开销；决定支持的最低系统与发行方式。
- 交付：可运行技术样机、系统行为记录、风险结论。
- 通过条件：普通桌面完整交互成立；锁屏/全屏支持边界有证据。若锁屏无法用合适的公开能力可靠观测，必须先调整计时口径并记录，不能悄悄声称已经支持。

### 阶段 1：能长期驻留的猫，3–4 天

- 菜单栏、浮层、拖动、坐标保存、基础动画、隐藏与恢复、屏幕变更处理。
- 交付：不接 AI 也能使用的桌面宠物。
- 通过条件：连续使用 2 小时，窗口可操作、不遮挡透明区、位置不会因断屏而丢失。

### 阶段 2：完整护眼行为，4–5 天

- 时间逻辑与持久化、系统事件对接、提醒状态、中央放大与回位、打断处理、免打扰。
- 交付：用短周期演示全部流程，并完成一次真实 90 分钟验证。
- 通过条件：真实计时只触发一次；稍后提醒不算休息；动画被中断仍能回到可用状态。

### 阶段 3：快捷问答，4–5 天

- 问答面板、快捷键、服务配置、连接测试、流式输出、停止、错误处理、Keychain。
- 交付：猫能够通过用户指定的兼容 API 回答短问题。
- 通过条件：至少 2 个独立的兼容服务通过契约测试，其中可包含本地服务；断网不影响护眼功能。

### 阶段 4：整合、美术与体验，4–6 天

- 接入正式素材、打磨节奏、减少动态效果、聊天与提醒冲突、首次使用、设置与清理。
- 性能测试与优化；在固定设备上记录功耗和资源占用，不只看开发机演示效果。
- 交付：可供小范围用户日常试用的 Beta。

### 阶段 5：兼容、长时间运行与发布，3–5 天

- 真机验证锁屏、唤醒、Spaces、全屏、外接屏断开、网络故障、重启恢复。
- 签名、公证、安装/升级/卸载验证，整理已知限制。
- 交付：可分发安装包、使用说明和测试记录。

关键路径：窗口与系统信号验证 → 桌面猫 → 计时与提醒闭环 → QA 接入 → 整合与发布。先证明产品独特的提醒体验成立，再扩展聊天能力。

## 7. 验收与测试清单

### 计时逻辑：用可控时钟测试

- [ ] 89:59 不提醒，达到 90:00 后只产生一个待提醒事件；正常调度下 2 秒内开始处理，免打扰等有意延迟除外。
- [ ] 没有键鼠活动的阅读场景仍累计；短暂停屏不清零，持续休息达到阈值后正确重置。
- [ ] 稍后 10 分钟、暂停、恢复、跳过、手动确认休息的结果符合第 3 节。
- [ ] 系统时间前后调整、重复事件、程序重开不会重复累计或连续弹窗。
- [ ] 免打扰到期、问答结束只释放一个待处理提醒。

### 真机行为：自动化不能替代的部分

- [ ] 用户在其他应用输入时，猫出现与提醒不会让字符进入猫的窗口。
- [ ] 走到猫所在屏幕中央并放大；结束后原屏幕不变时回到原位置，误差目标不超过 4 个逻辑点。
- [ ] 屏幕断开时采用新的有效位置；坐标使用逻辑点，覆盖不同缩放比例与屏幕排列。
- [ ] 提醒中拖动、打开聊天、锁屏、休眠、关闭提醒，都能正常结束或恢复。
- [ ] 普通窗口、Spaces、全屏和 Stage Manager 分别记录实际支持情况；不会对系统保护界面做覆盖承诺。
- [ ] 一次真实 90 分钟周期和至少一次 8 小时常驻测试通过；短周期演示不能替代真实周期验证。

### API 与数据

- [ ] SSE 跨网络分片、非流式、用户停止、超时、401/429/5xx 均有可理解的反馈。
- [ ] 修改服务或模型时结束旧请求、清空旧上下文；未经用户操作不向新服务转发旧会话。
- [ ] 密钥不进入普通配置、源码或日志；模型返回内容只能显示，不执行脚本、命令或自动打开链接。
- [ ] API 不可用时，拖动、菜单栏、计时和提醒正常工作。
